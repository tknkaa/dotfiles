PR の差分についての選択式クイズを出し、ユーザーがその変更をどれだけ理解しているかを測る。

## 手順

1. **差分を取得する。** 引数は PR 番号。`gh pr view <番号>` で目的・説明を、`gh pr diff <番号>` で差分を読む。必要なら関連ファイルの周辺コードも読む。番号がなければユーザーに聞く。
2. **問題を作る。** 差分の大きさに応じて数を決める。小さい差分は 3〜5 問、大きい差分は多めにする。次を中心に出す。
   - なぜその変更が必要か(目的、背景)
   - 変更前後の挙動の違い
   - 壊れうる箇所、副作用、見落としやすい前提
   - 差分に現れない決定(なぜ別の方法を選ばなかったか)は、PR 本文やコードから根拠が読める場合だけ出す
3. **一問ずつ出す。** AskUserQuestion で選択式にし、次の問題は回答を受け取ってから出す。まとめて出さない。
   - 選択肢は 3〜4 個。正解が一つに定まり、誤答は「ありそうな誤解」にする。
   - 正解の位置は偏らせない。選択肢のラベルで正解が分からないようにする。
   - 答えを推測で決めない。根拠は差分、PR 本文、コードから読み取れるものだけにする。
4. **回答ごとにフィードバックする。** 正解か不正解かを示し、根拠になる差分の箇所(`file:line`)を添えて 1〜3 文で解説する。不正解のときは、なぜその選択肢が誤りかも述べる。
5. **最後に総括する。** 正答数、理解できていた点、弱かった点を短くまとめる。弱かった点は、読み直すと良いファイルや箇所を挙げる。

## 守ること

- 差分を読む前に問題を作らない。
- クイズ中に差分の答えを先に漏らさない。
- 評価はユーザーの理解についてのみ行う。PR の良し悪しのレビューはしない。
